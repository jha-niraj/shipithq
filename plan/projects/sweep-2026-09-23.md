# Projects sweep, 2026-09-23

A read of the whole module, UI and functionality, after the Explore rebuild.
20 findings. What was fixed, and what is still open with the reason.

## Fixed

**Money**
- **Mock interviews were free after the first.** The 30 credits were taken when the
  knowledge base was built, and that call returns early once one exists, so every
  interview after it cost nothing: minutes of speech plus a completion for the
  feedback, unlimited, per project. The charge is now per session, where the cost is.
- **Anyone could enrol for free.** `startProject` had no owner check while
  `enrollInProject` beside it charges 13 credits for the same outcome. It is the
  creator's own start now; everybody else enrols.
- **Sprint generation was open to anyone.** It checked only that the project
  existed, so any signed-in user could run unbounded completions on our key
  against any project id. It requires the creator, and is single-flight per project.
- **Project generation could run twice.** No single flight, and the worker debits
  credits itself, so a double click was two projects and two charges.

**Who can touch what**
- A private project was served to anyone holding the slug, sprints and tasks
  included. Now only its creator or someone enrolled.
- A mock session's completion was written by session id alone, so anyone could
  overwrite somebody else's transcript, score and feedback.
- `addTaskToSprint` had no ownership check at all, and never checked the sprint
  belonged to the project it was given.
- `addSprintToProject` took an `autoAccept` flag that let a non-creator write an
  approved, shared sprint into somebody else's project. The flag is gone.
- The quiz page selected `correctAnswer` and `explanation` for every question and
  sent them to the browser before the attempt. Submitting still returns them.

**Stuck**
- A quiz retake hit the unique index on (user, quiz), surfaced as "Failed to
  submit quiz", and could never finish. A retake overwrites its attempt now.

**UI**
- "Build this" on Explore passed EASY/MEDIUM/HARD into a form that takes
  BEGINNER/INTERMEDIATE/ADVANCED, so Generate failed on a raw validation error.
  One mapping, used by both the cards and the picks.
- Explore's "New project" linked to a parameter the hub does not read, so the
  page's primary action navigated away and did nothing. The sheet opens in place.
- Explore had no `loading.tsx`, so the Community and Mine tabs painted nothing.
- The error categories used pink, slate and grey against the monochrome rule.

## Closed on 2026-09-23, after Niraj's answers

All seven. See PJ-7 in `tasks.md` for what changed in each file.

- **The worker's unguarded credit debit** is gone. Project generation holds its
  credits at dispatch like every other job (`startBackgroundJob({ cost })`),
  which reserves under a SQL balance guard and refunds if the job fails. The
  worker no longer touches credits at all.
- **A quiz job that finds one already there now throws**, so the 25-credit hold is
  released instead of settled.
- **Sprint numbering** recomputes `max + 1` inside a retry on the unique index.
  It was not only a race: a personal sprint takes a number on the shared project,
  so the next person's insert collided every time.
- **A dropped voice call** is closed and refunded. The hold is keyed on the session
  id and stays open for the length of the call: settled when a transcript is
  saved, released when the call recorded nothing. An hourly sweep closes what the
  browser never got to.
- **One `updateTaskStatus`**, the one that recalculates progress. The other was
  what the sprints page called, which is why ticking a task there never moved the
  bar that gates the quiz at 50% and the mock at 75%.
- **The sprints page** asks once for every sprint's completion status.
- **The three dead files** are deleted, 1,540 lines, with Niraj's approval.

### The one thing to get right at deploy time

`apps/worker` must ship BEFORE `apps/main`. The app now holds the credits for a
project generation; the worker in production still debits them itself. Ship the
app first and a generation is charged twice for as long as the gap lasts.

## Was still open, and why


- **The worker's credit debit is unguarded** (`apps/worker/src/pipeline.ts`): it
  writes `credits - cost` with the only balance check at dispatch, so two queued
  jobs can drive a balance negative. Needs a conditional update in the worker,
  which is a worker deploy rather than an app change.
- **A quiz job that finds one already there completes rather than failing**, so the
  hold settles and the user is charged 25 for nothing.
- **Sprint numbering collides**: `last + 1` against a unique index, so two people
  adding a sprint to the same project at once get "Failed to add sprint".
- **A dropped voice connection leaves a mock IN_PROGRESS forever**: the completion
  only runs when the user ended it deliberately.
- **Two `updateTaskStatus` actions exist**, one of which never recalculates
  progress, and both are check-then-insert against a unique index.
- **The sprints page fires one server action per sprint** on mount, in series.
- **Dead files**: `components/projects/project-analytics.tsx`,
  `app/(main)/projects/_components/recent-submissions-grid.tsx` and
  `app/(main)/projects/ideas/_components/ProjectIdeasClient.tsx` have no importers.
  Deletions are proposed, never assumed, so they wait for Niraj.
