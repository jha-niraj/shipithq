How Claude Code ended up running in your browser tab

You opened localhost:7070, pressed a button, got a terminal, signed in to Claude, and Claude rewrote src/app.js. This guide explains every piece between that button and that edit, from scratch, with the real code and the real lines your session recorded.

The whole thing in one paragraph. Your Mac runs a small Node program (the host server). When you press Start, it asks Docker to start a fresh little Linux computer (a container) that already has Node, git and Claude Code installed. Inside that container, a second small program (the agent) opens a real Linux shell and streams it to your browser over a live connection, so your keystrokes go in and the shell's output comes back. Claude Code runs in that shell like on any laptop. Every time Claude does something, Claude Code itself calls a tiny script we installed (a hook), and the agent writes that down. After each of Claude's turns the agent saves the code as a git commit and copies it to a folder on your Mac. The replay page reads only that folder, so it still works when the container is gone.

Words you will meet

Every chapter uses these. None of them is hard; each is a name for something simple.

Docker image
A frozen snapshot of a Linux computer with programs already installed: Node, git, Claude Code, our agent, the starter repo. Built once from the Dockerfile (a recipe). Ours is called shipithq-sandbox:dev and is 2.18 GB.
Container
A running copy of the image. Starting one takes under a second because nothing is installed at start; everything is already in the image. Each session gets its own, and deleting it deletes everything inside it.
Host
The machine running Docker: your Mac. Anything "on the host" survives a container being deleted.
Port
A numbered door on a computer that a program listens behind. Our host server listens on 7070; the agent listens on 8080 inside its container; Docker connects a random door on your Mac (like 32770) to that 8080.
WebSocket
A phone call between the browser and a server: once connected, both sides can talk at any time. Ordinary web requests are letters (ask, get one answer). A terminal needs the phone call.
PTY
"Pseudo-terminal". A fake keyboard and screen that a program like bash can't tell from a real one. It is how a terminal gets inside a web page (chapter 2).
Bind mount
Plugging a folder from the host into the container, like a USB drive. Both sides see the same files at the same time.
Bare git repo
A git repository with only the history, no working files. It is what GitHub keeps on its side. Ours (repo.git) is the "remote" we push every checkpoint to.
Hook
A command Claude Code runs on its own at set moments: when you send a prompt, before and after each tool it uses, and when it finishes a turn. We use hooks to record what Claude did.
root / candidate
Two Linux users inside the container. root can do anything; our agent runs as root. candidate is an ordinary user; your shell and Claude run as candidate. The gap between the two is the whole safety story (chapter 4).
