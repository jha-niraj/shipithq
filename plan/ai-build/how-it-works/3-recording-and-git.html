Recording and git

We never record the screen. We record what happened, as one line of text per event, and we save the code as git commits. Four sources feed the recording; one file holds it; one repo holds the code.

Hooks, from scratch

Claude Code has a built-in feature: at certain moments it runs a command you configure and hands it a description of what is happening, as JSON on its input. It is designed for exactly this kind of thing (auditing, checks, notifications). We use five moments:

apps/sandbox/image/managed-settings.json → /etc/claude-code/managed-settings.json

{
  "hooks": {
    "SessionStart":     [{ "hooks": [{ "type": "command", "command": "node /opt/agent/hook.mjs", "timeout": 5 }] }],
    "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "node /opt/agent/hook.mjs", "timeout": 5 }] }],
    "PreToolUse":  [{ "matcher": "*", "hooks": [{ "type": "command", "command": "node /opt/agent/hook.mjs", "timeout": 5 }] }],
    "PostToolUse": [{ "matcher": "*", "hooks": [{ "type": "command", "command": "node /opt/agent/hook.mjs", "timeout": 5 }] }],
    "Stop":             [{ "hooks": [{ "type": "command", "command": "node /opt/agent/hook.mjs", "timeout": 5 }] }]
  }
}
SessionStart
You typed claude and it started.
UserPromptSubmit
You pressed Enter on a prompt. The JSON includes "prompt", your exact text.
PreToolUse
Claude is about to use a tool. Includes "tool_name" (Bash, Edit, Write, Read...) and "tool_input" (the command, or the file and the change).
PostToolUse
The tool finished. Adds "tool_response" (its output) and "duration_ms".
Stop
Claude finished its turn and is waiting for you. Includes "transcript_path", the conversation's log file.

Why the file lives in /etc/claude-code/: that is where Claude Code looks for managed settings, the ones a company sets for every user. They apply on top of anything the user sets, and because root owns the file, the candidate can read it but can't remove the hooks. (A determined candidate could still stop them in other ways; chapter 4.)

The hook script itself is tiny. It must never slow Claude down or break it, so it hands the JSON over and always exits successfully:

apps/sandbox/image/agent/hook.mjs

let input = ""
process.stdin.on("data", (c) => { input += c })        // Claude Code writes the JSON here
process.stdin.on("end", async () => {
    try {
        await fetch("http://127.0.0.1:8080/hook", {        // the agent, in the same container
            method: "POST", headers: { "content-type": "application/json" },
            body: input, signal: AbortSignal.timeout(2000),
        })
    } catch { /* recording must never get in Claude's way */ }
    process.exit(0)                                      // 0 = "carry on"
})

The agent turns each hook into an event

apps/sandbox/image/agent/server.mjs

function onHook(h) {
    const base = { claudeSession: h.session_id }
    switch (h.hook_event_name) {
        case "UserPromptSubmit":
            lastPrompt = String(h.prompt ?? "")
            record("prompt", { ...base, text: clip(lastPrompt) })
            break
        case "PreToolUse":
            record("tool.start", { ...base, id: h.tool_use_id, tool: h.tool_name, input: clip(h.tool_input) })
            break
        case "PostToolUse":
            record("tool.end", { ...base, id: h.tool_use_id, tool: h.tool_name, input: clip(h.tool_input), response: clip(h.tool_response), ms: h.duration_ms })
            break
        case "Stop": {
            const text = h.transcript_path ? assistantTextSince(h.transcript_path) : ""   // Claude's words
            record("turn.end", { ...base, text: clip(text) })
            turn += 1
            void checkpoint(`Turn ${turn}: ${lastPrompt.split("\n")[0].slice(0, 72)}`)   // save the code
            break
        }
    }
}

clip cuts anything over 20,000 characters (a huge test output, say) and notes the full size, so one tool call can't balloon the file.

Writing an event: one line, appended

let seq = 0                                              // event number, 1, 2, 3...
function record(type, data = {}) {
    seq += 1
    const line = JSON.stringify({ seq, ts: new Date().toISOString(), type, ...data })
    fs.appendFileSync("/root/remote/events.jsonl", line + "\n")   // straight onto your Mac
}

Because /root/remote is the session folder on your Mac (chapter 1, the -v flag), each line is on the host the moment it is written. A container crash a second later loses nothing already recorded.

Your commands, from the shell

Claude's commands come through hooks. Commands you type need another way in. bash runs PROMPT_COMMAND every time it is about to show the prompt again, which happens right after a command finishes:

apps/sandbox/image/bashrc.sh (added to the candidate's .bashrc)

__sbx_log() {
    local c
    c=$(HISTTIMEFORMAT= history 1 | sed 's/^ *[0-9]* *//')          # the command just run
    if [ -n "$c" ] && [ "$c" != "$__sbx_last" ]; then
        __sbx_last="$c"
        ( curl -s -m 1 -X POST --data-binary "$c" http://127.0.0.1:8080/command >/dev/null 2>&1 & )
    fi
}
PROMPT_COMMAND="__sbx_log${PROMPT_COMMAND:+;$PROMPT_COMMAND}"
cd /workspace 2>/dev/null

Side effect worth knowing: a command is recorded when it ends. Your claude was recorded as event 19, after you quit Claude, not at the start.

There are two git repositories for every session. The candidate works in one; the other is the safe copy on your Mac.

The checkpoint, in code

function checkpoint(message) {
    // One at a time: a Stop hook and a Submit can arrive together.
    checkpointing = checkpointing.then(async () => {
        await asCandidate(["add", "-A"])                                         // stage everything
        const dirty = await asCandidate(["diff", "--cached", "--quiet"]).then(() => false, () => true)
        if (!dirty) return null                                                 // nothing changed: no commit
        await asCandidate(["commit", "-q", "-m", message])
        const sha = (await asCandidate(["rev-parse", "HEAD"])).stdout.trim()
        const stat = (await asCandidate(["show", "--stat", "--format=", sha])).stdout.trim()
        await push()
        record("checkpoint", { sha, message, stat })
        return sha
    })
    return checkpointing
}

// Pushed by URL, not a remote name, so root never writes a tracking ref into the candidate's repo.
const push = () => asRoot(["-C", "/workspace", "push", "-q", "/root/remote/repo.git", "HEAD:refs/heads/main"])

Why push by path instead of the usual git push origin? A normal push also writes a small "where origin is now" file inside /workspace/.git. Root would own that file, and the next time the candidate (or Claude) ran git fetch it would fail with "permission denied". Pushing straight to the path writes nothing on the candidate's side.

Why the push runs as root: only root can open /root/remote. The candidate can make commits; only the agent can copy them out.

Your edits in the side editor

When you press Save, the agent compares the old and new text with git's diff tool and records the difference, then writes the file as the candidate:

async function saveFile(rel, content) {
    const abs = inWorkspace(rel)                          // refuses ../../etc/passwd and friends
    const before = fs.existsSync(abs) ? fs.readFileSync(abs, "utf8") : ""
    if (before === content) return                        // nothing changed: nothing recorded
    ...
    fs.writeFileSync(abs, content)
    fs.chownSync(abs, 1000, 1000)                         // still the candidate's file
    const diff = await run("git", ["diff", "--no-index", "--no-color", tmpBefore, abs])
    record("human.edit", { path: rel, diff: clip(diff) })
}
