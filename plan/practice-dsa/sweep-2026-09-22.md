# Practice and DSA sweep, 2026-09-22

A read of the whole module, UI and functionality, asked for by Niraj. 38 findings.
What was fixed in this pass, and what is still open, with the reason.

## Fixed

**Money and data**
- `updateSessionAfterAssess` took `score` and `xpAwarded` straight from the browser and wrote them to the session, the user's XP and the leaderboard. A hand-made call could mint XP. Both are now bounded server-side (score 0-100, XP at most 120) and an empty `requirementsMet` no longer counts as "all met". The real fix is PD-18.
- `generateProblemFromURL`, `generateProblemFromName` and `createUserPracticeProblem` were still exported and callable after the Add problem control came off the page: an uncharged Exa fetch plus a gpt-4o call each, and a write into the catalogue every user reads. All three are admin-only now.
- `requestJudgeAssets` refused only `ready`, so a problem already `generating` accepted a second dispatch: two Durable Objects doing the same six model calls. It now refuses `generating` too.

**Work that was being lost**
- The 30-second autosave closed over the store snapshot taken at mount, so `isDirty` was permanently false and it saved nothing, ever. It reads live state now, saves when the tab is hidden or closed, and does not mark the work clean when the save failed.
- `finishGuidedSession` wrote stage `done` before the reflect job ran. A failed job left a session that could not be finished and had no XP. The stage moves in `applyGuidedCompletion` now, and the Finish button accepts `done` with the session still in progress.
- `updateModuleProgress` and the leaderboard write were both check-then-insert against a unique index. Two completions landing together threw after the session was already complete. Both are upserts.

**What the screen said**
- The workspace used `h-dvh`, one bottom-bar taller than its container below lg, so the composer sat under the fixed bottom bar. It uses `--page-h`.
- The stage tracker drew finished steps faint and unreached steps in ink, so progress read backwards; the current step's border was invisible on white.
- Hover states in the system-design library and the API tester turned text near-black on a near-black fill in light mode.
- The practice hub's cards had no surface over the shell backdrop; small grey text on it measured about 1.3:1.
- A met requirement had no dark variant, about 2.8:1 on the workspace.
- The API tester called any reply containing the word "pass" a PASS, so "this does not pass" showed green. The verdict is the first word now.
- The editor rendered its placeholder comment AS the code, so Run answered "write some code first" against visible text.
- Backend problems stacked panels adding to 140% of the column and rendered an HTML preview of server code. Frontend keeps the preview; backend gets 60/40 with the API tester.
- The Send button and the back control had no accessible name; back is a link now.
- The practice hub skeleton was capped at `max-w-6xl` with no chart row, and the module list skeleton still drew the topic chips the dropdown replaced.
- The path's quiz row named a plan file at the user; it says what is not ready in their terms.
- The path's timed problem showed the exam-set price for a link that opens a normal exam session.

## Fixed in the second pass (same day)

- **PD-18, done.** `assessPracticeWork` now writes the session itself through a
  server-only `persistAssessment`. The score and the XP never travel through the
  browser, and `updateSessionAfterAssess` is gone. The model's own score is
  clamped before it is used, so an unparseable reply cannot put 50 on the
  leaderboard either.
- **The mentor-state lost update.** `settleStage` re-reads the row before writing,
  so a Submit that lands while a reply streams keeps its `testsPassedAt` and brute
  force advances.
- **Session saves are conditional.** `saveSessionProgress` takes the `updatedAt`
  the client last saw and refuses a write against a newer row, so a second tab or
  the judge's own write is not clobbered.
- **Deleting a memory entry is conditional too**, and retried against fresh state,
  so the consolidation job can no longer bring back something you deleted.
- **Memory jobs are single-flight per SESSION**, through a new `singleFlightKey`,
  so a consolidation for one problem no longer swallows another problem's.
- **Uncharged model calls are rate limited.** Re-plan, Refresh and Pick again each
  refuse a second run within a minute, using the time already stored on the row.
  Submit refuses a second assessment of the same session within fifteen seconds.
- **Dashboard counts.** "Attempted" counts every session rather than the page of
  ten it displays; a problem with both an exam and an assist session reports the
  completed one rather than whichever the database returned first.
- **The workspace stacks below lg.** The three columns become vertical panels,
  each scrolling and resizable, instead of a 95px problem statement on a phone.
